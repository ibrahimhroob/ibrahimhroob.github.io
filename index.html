Production work · JABAS.AI navigation stack

A GPS-free navigation stack for agricultural robot fleets

JABAS.AI spun out of the University of Lincoln and Ceres Agri-Tech in 2026 to provide autonomy-as-a-service for farm robots, and I lead its autonomy work. The problem is real and close to home. On soft-fruit farms, up to a fifth of the work is moving trays of picked fruit, often under polytunnel plastic where GPS can't be trusted. Our stack lets robots from different manufacturers do that job without GPS. It runs on the AgileX Hunter, Dynium Gophar and Dogtooth platforms from one codebase, in simulation and on hardware, and is in on-farm trials with commercial growers.

The part I enjoy most is the loop between a derivation on the whiteboard and a robot driving a real polytunnel row, with the field logs showing what to improve next.

jabas_lio

Sole author · written from scratch

Tightly coupled LiDAR-inertial odometry for ROS 2. A sliding-window factor graph fuses 200 Hz IMU with 10 Hz Livox Mid-360 scans and estimates pose, velocity and IMU bias jointly. It was built for crop rows and tunnels, where the geometry is repetitive and scan matching alone degenerates.

  • GTSAM IncrementalFixedLagSmoother (iSAM2) with CombinedImuFactor and bias feedback into preintegration
  • Per-point IMU deskewing, voxel map with incremental PCA normals, robust point-to-plane matching
  • Custom GTSAM factors for wheel-odometry and command-velocity motion priors. Their weights adapt to LiDAR observability.
  • Frame-health gating, stationary locking, published covariances, and a GPS fusion node
  • Synthetic LiDAR/IMU generator for hardware-free tests; replay and benchmark tooling

C++17 · Python · GTSAM · Eigen · ROS 2 · ~9.6k lines · 12 test suites

7.9 cmaligned position RMSE over 4,800 field scans (8 min), GPS used only as reference
8.3 mmmax error while stationary over 20 s, with zero false path length
30–65 msper-frame cost inside a 100 ms budget, so it holds 3× real-time replay
−21%CPU from profile tuning for +5 mm RMSE, measured over the full bag

nav2_costmap_row_controller

Author

A Nav2 controller plugin for Ackermann robots in polytunnel rows. It finds the row boundaries in the costmap or point cloud, infers corridor width on its own, and keeps going when it can only see one side. It travels the exact planned distance even when localization drifts. I validated it with a deterministic harness that ran the real Nav2 costmap code: 18 runs and 6,338 control cycles.

C++ · Nav2 plugin API · costmap_2d · GitHub Actions CI

nav2_mppi_controller

Lead

I backported Nav2's latest MPPI controller into the stack and added a four-wheel-steering motion model for the Gophar platform, with tests. I also built "MPPI Control Room", a web UI for live telemetry, velocity monitoring and critic tuning on the robot.

C++ · xtensor · MPPI · JavaScript

navstack_bringup

Author

Launch and orchestration for the whole stack. It covers GNSS, LIO, point-cloud preprocessing, Nav2, EKF/NavSat fusion, topological navigation, metrics and command safety guards. One codebase handles three platforms on both real hardware and Gazebo, with per-platform Docker devcontainers.

Python launch · Docker · robot_localization · tmule

topological_navigation

Contributor to LCAS's open-source topological planner, which has 1,700+ commits. I worked on the ROS 2 port and added per-route-segment metric maps and occupancy-grid publishing. Edge actions can now set ROS 2 parameters on any node, and I wrote topomap editing and image-export tools.

autonomy_metrics_logger

Author

Tracks autonomous and manual distance, interventions and collisions, and logs each event to MongoDB with a full system snapshot. It reports mean distance between interventions (MDBI) and is the source of truth for distance-based billing. If MongoDB goes down, the node keeps running and reconnects in the background.

Research · first author

Which parts of a changing world can a robot trust?

My PhD asked which LiDAR points stay stable over weeks and seasons, and how to learn that without manual labels. The result is a family of self-supervised point-stability filters that make scan-to-map localization robust in dynamic environments.

IEEE RA-L2024 · vol 9(4)

Generalizable Stable Points Segmentation for 3D LiDAR Scan-to-Map Long-Term Localization

I. Hroob, B. Mersch, C. Stachniss, M. Hanheide

Learns per-point stability from 3D LiDAR alone and generalizes across environments, improving long-term scan-to-map localization. Joint work with Cyrill Stachniss's lab at the University of Bonn.

DOIPDFCodeVideo
Robotics and Autonomous Systems2024 · vol 181

Adaptive Robot Localization in Dynamic Environments through Self-Learnt Long-Term 3D Stable Points Segmentation

I. Hroob, S. Molina, R. Polvara, G. Cielniak, M. Hanheide

Unsupervised spatio-temporal labelling plus a stability regression network. Using only long-term stable points gives more reliable localization on long missions than using the full scan.

DOILabelling code
ECMR2023 · Coimbra

Learned Long-Term Stability Scan Filtering for Robust Robot Localisation in Continuously Changing Environments

I. Hroob, S. Molina, R. Polvara, G. Cielniak, M. Hanheide

A stability scan filter for agricultural fields. It drops points that will not persist before they reach localization.

IEEECodeZenodo

LTS-NET: End-to-End Unsupervised Learning of Long-Term 3D Stable Objects

I. Hroob, S. Molina, R. Polvara, G. Cielniak, M. Hanheide

Learns continuous point-wise stability labels from historical scans. It beats direct static-versus-dynamic classification on NCLT.
